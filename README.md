## 🧭 How I Approach System Design

I try to make every application **readable**, **effective**, and **maintainable**. Here is what that looks like in my projects:

| Principle | What I do in practice |
|---|---|
| 📖 **Readable** | Clear layering and naming, one responsibility per module, typed contracts, and consistent team code-quality and version-control guidelines |
| ⚡ **Effective** | Right tool for the job: compile-time-checked SQL (Cornucopia), async background workers (RabbitMQ), local LLMs via Ollama, and retrieval grounded in real data |
| 🔧 **Maintainable** | One-directional dependencies, SOLID, Repository/Unit of Work, CQRS, swappable components (e.g. LLM and embedding models configurable without code changes) |
| 🧪 **Testable** | Unit tests with fixed ID/clock doubles, HTTP-level integration tests against a real database, and CI that builds and tests on every change |
| 🔍 **Observable** | Structured logs and request tracing with request-ID spans, latency, and error codes, so one ID links the request, the error, and the domain events. Toolkit: **OpenTelemetry** (traces/metrics), **Prometheus** + **Grafana** (metrics and dashboards), **Langfuse** (LLM tracing, prompt and RAG evaluation) |
| 🔒 **Secure & scalable** | JWT authentication, typed public errors that never expose internal causes, and event-driven messaging to decouple services |

**Patterns and styles I use:** Clean Architecture · CQRS · SOLID · Repository & Unit of Work · Strategy · Pipeline/Decorator · Microservices · Event-Driven Architecture

## 🚀 Featured Projects

### 🛒 Ahlan Commerce: E-Commerce Product API
`Rust` `Axum` `React` `PostgreSQL` `Atlas` `Cornucopia` `tracing` `Docker` `CI/CD`

A product catalog REST API built as a layered Rust workspace (HTTP crate, domain library, data-access crate) with one-directional dependencies and a typed public error contract that never leaks internal causes.

- Structured logs and request tracing with request-ID spans, latency, and error codes
- SQL-first data layer: Atlas migrations and Cornucopia compile-time-checked queries
- Unit tests with fixed ID/clock doubles plus HTTP-level integration tests against a real database
- React front end and a CI/CD pipeline that builds and tests the workspace automatically

### 📞 Telecom Egypt: Intelligent Assistant
`Streamlit` `RAG` `ChromaDB` `faster-whisper` `TTS` `Ollama`

An on-premises, bilingual (Arabic / English / Egyptian dialect) RAG assistant with voice and text input, document upload, and source-cited answers.

- Speech pipeline: faster-whisper ASR → retrieve-and-generate RAG → MMS-TTS / XTTS-v2 voice replies
- ChromaDB retrieval with BGE-M3 / e5 embeddings over a scraped te.eg knowledge base and user-uploaded PDF/DOCX/TXT/image files
- LLM served locally via Ollama (Llama 3.1 8B / Qwen2.5, swappable in config)

### 🎓 CourseApp: E-Learning Platform with RAG AI Chat
`.NET 9` `Angular 20` `PostgreSQL + pgvector` `RabbitMQ`

A full-stack e-learning platform with an AI assistant that answers questions grounded in course content.

- Clean Architecture backend with CQRS (MediatR), AutoMapper, and Repository/Unit of Work
- RabbitMQ-driven worker that extracts, chunks, and embeds uploaded materials asynchronously
- RAG with pgvector, Ollama/Jina embeddings, and Ollama/Groq generation; JWT auth and Angular 20 chat UI

### 🏭 Graduation Project: Adaptive Industrial Predictive Maintenance System
`Microservices` `RabbitMQ` `RAG` `LangGraph` `LSTM`

Real-time Remaining Useful Life (RUL) forecasting with LSTM, Agentic RAG diagnostics (LangGraph) over failure data, and a Human-in-the-Loop core. I designed and owned the RabbitMQ event-driven messaging across the microservices.
